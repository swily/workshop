## 4) HTTPS Enablement Plan (for consolidated or existing ALBs)
Target benefits: HTTP/2, secure transport, browser friendliness, possible perf gains.

A) Annotations to add to Ingress resources exposed publicly:
- `alb.ingress.kubernetes.io/listen-ports: '[{"HTTPS":443},{"HTTP":80}]'`
- `alb.ingress.kubernetes.io/certificate-arn: <ACM_CERT_ARN_FOR_GREMLINPOC_COM>`
- `alb.ingress.kubernetes.io/ssl-redirect: '443'`
- Optional: `alb.ingress.kubernetes.io/actions.ssl-redirect` (for complex rulesets)

B) Where to apply:
- Consolidated path-based ingress (`consolidated-demo-ingress`) OR
- Each existing ingress (frontend, otel-grafana, otel-prometheus) if keeping multiple ALBs.

C) Steps:
1. Obtain the ACM certificate ARN for `gremlinpoc.com` (wildcard cert recommended).
2. Patch ingress annotations (prefer consolidated ingress to keep it centralized).
3. Apply changes; confirm ALB shows :443 listener and certificate attachment.
4. Test:
   - `curl -I https://demo-frontend.gremlinpoc.com/` should return 200/3xx and negotiate HTTP/2.
   - HTTP requests should be redirected to HTTPS.

Notes:
- If Grafana/Prometheus are served under subpaths, ensure they work under path prefixes (Grafana is typically fine; Prometheus UI under `/prometheus` may require reverse-proxy prefix handling—validate UI assets load.)

## 5) Frontend Delivery Improvements (post-HTTPS)
- Enable compression for HTML at `frontend-proxy` (Envoy gzip/brotli filter) to reduce transfer size.
- Keep Next.js static assets with `cache-control: public, max-age=31536000, immutable` (already good).
- Consider enabling HTTP/2 + TLS session resumption for faster subsequent loads.
