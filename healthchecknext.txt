## Options Moving Forward:

### Option A: Use Existing + Add Prometheus Path (RECOMMENDED)
**Grafana:**
- URL: https://monitoring.gremlinpoc.com/api/health ✅ (already working)

**Prometheus:**
- Update monitoring-ingress to add /prometheus path
- URL: https://monitoring.gremlinpoc.com/prometheus/api/v1/alerts
- Requires: Ingress modification to add path-based routing

**Pros:**
- Single domain for all monitoring
- Both services HTTPS accessible
- No PNI complexity
- Clean, simple URLs

**Cons:**
- Requires ingress update
- Path-based routing adds slight complexity

**Implementation:**
```yaml
# Add to monitoring-ingress
- path: /prometheus
  pathType: Prefix
  backend:
    service:
      name: kube-prometheus-stack-prometheus
      port:
        number: 9090
```

### Option B: Use Internal Kubernetes URLs with PNI
**Grafana:**
- URL: https://monitoring.gremlinpoc.com/api/health ✅

**Prometheus:**
- URL: http://kube-prometheus-stack-prometheus.monitoring.svc.cluster.local:9090/api/v1/alerts
- Requires: Gremlin Private Network Integration (PNI) setup

**Pros:**
- No infrastructure changes
- Uses existing setup

**Cons:**
- PNI setup complexity
- No external HTTPS for Prometheus
- Harder to test/debug

### Option C: Create Separate Prometheus Ingress
**Grafana:**
- URL: https://monitoring.gremlinpoc.com/api/health ✅

**Prometheus:**
- New ingress: prometheus.gremlinpoc.com
- URL: https://prometheus.gremlinpoc.com/api/v1/alerts

**Pros:**
- Clean separation
- Both have dedicated domains
- Both HTTPS

**Cons:**
- Additional ALB cost
- More DNS records to manage
- More complex infrastructure
