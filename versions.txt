How versions are configured
- Installer: scripts/gremlin_install.sh
  - Uses Helm chart gremlin/gremlin (0.24.1)
  - Enforces Helm-managed secret (Option A):
    - gremlin.secret.managed=true
    - gremlin.secret.type=secret
    - gremlin.secret.teamID, gremlin.secret.teamSecret
    - gremlin.teamID, gremlin.clusterID
    - chao.create=true (enables chao Deployment)
  - NOTE: We do not override image tags in values; chart defaults result in the images above (":latest"). The effective pinned artifact is the image digest (shown above).

- Annotations and Agent Env: config/gremlin/gremlin_annotations.sh
  - Adds gremlin.com/* annotations to Services and Deployments
  - Ensures Kubernetes app.kubernetes.io labels on pod templates
  - Patches Gremlin DaemonSet env (GREMLIN_CONTAINER_LABELS, GREMLIN_CLIENT_TAGS, etc.)
  - Restarts deployments and verifies RBAC

Reproduce locally
- Chart and release info:
  - helm list -n gremlin
  - helm show chart gremlin/gremlin | sed -n '1,40p'
- Images and digests:
  - kubectl -n gremlin get ds/gremlin -o jsonpath='{.spec.template.spec.containers[0].image}'
  - kubectl -n gremlin get deploy/chao -o jsonpath='{.spec.template.spec.containers[0].image}'
  - kubectl -n gremlin get pods -l app.kubernetes.io/name=chao -o jsonpath='{.items[0].status.containerStatuses[0].imageID}'
  - kubectl -n gremlin get pods -l app.kubernetes.io/name=gremlin -o jsonpath='{.items[0].status.containerStatuses[0].imageID}'

Recommendations
- For production stability, consider pinning explicit image tags (agent and chao) instead of ":latest". The installer can be extended to accept --agent-version and --chao-version and pass them as Helm values to override defaults.
